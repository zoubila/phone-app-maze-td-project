LIRE ET MODIFIER LE CODE DE MAZE TD

Ce projet est écrit en GDScript, le langage de Godot. Les fichiers sont
maintenant séparés par sujet pour que vous puissiez en lire un à la fois.
Vous pouvez les ouvrir dans l'éditeur de Godot ou dans votre éditeur de texte.

PAR OÙ COMMENCER ?
1. Ouvrez main.gd et cherchez _ready : Godot y prépare l'application.
2. Ouvrez game.gd et cherchez reset : vous y trouverez l'état initial d'une partie.
3. Pour une première règle concrète, lisez build dans gameplay/construction.gd.
   Cette fonction vérifie un achat, teste le passage des monstres, puis retire l'or.
4. Lisez tick, puis combat_step dans gameplay/simulation.gd pour suivre le combat.
5. Choisissez ensuite le sujet qui vous intéresse dans le plan ci-dessous.

POURQUOI CERTAINES FONCTIONS DE GAME.GD SONT-ELLES TRÈS COURTES ?
L'interface appelle toujours game.build, game.sell ou game.tick : elle n'a
pas besoin de connaître tous les fichiers qui réalisent ces actions.
Ces courtes fonctions transmettent la même partie au fichier spécialisé.
Par exemple, game.sell appelle Construction.sell(self, cell).
self signifie « cet objet-ci » : il ne crée pas une deuxième partie.
Pour lire le détail de la vente, ouvrez gameplay/construction.gd.
Le but est de garder les données au même endroit et les règles rangées par sujet.

COMMENT SUIVRE UNE ACTION : VENDRE UNE TOUR
1. board.gd reçoit le clic et identifie la tour avec pick_item.
2. Un signal prévient main.gd, qui sélectionne cette tour et ouvre sa fiche.
3. Le bouton Vendre appelle sell_tower, puis game.sell.
4. gameplay/construction.gd rembourse l'or et retire la construction.
5. gameplay/navigation.gd recalcule les distances des monstres au château.
6. ui/update_interface.gd actualise l'or et les boutons.
7. rendering/board_renderer.gd dessine la carte sans la tour vendue.

COMMENT LE TEMPS ET LE DESSIN SONT-ILS SÉPARÉS ?
Godot appelle main._process à chaque image.
Cette fonction transmet le temps écoulé à game.tick, puis à simulation.gd.
Le combat avance par petits intervalles de 1/60 seconde de jeu.
combat_step appelle les étapes dans un ordre explicite : apparitions,
poison et déplacements, attaques, récompenses et fin éventuelle de vague.
Le dessin vient ensuite représenter ces données. Dessiner une flèche ne
retire pas de points de vie : les dégâts sont déjà décidés dans tower_combat.gd.

OÙ MODIFIER UNE VALEUR OU UN DESSIN ?
Prix, dégâts, portée et cadence : gameplay/tower_catalog.gd, dans TYPES.
Progression des points de vie : enemy_health dans gameplay/waves.gd.
Composition des vagues : wave_plan dans ce même fichier.
Prix d'amélioration et remboursement : gameplay/construction.gd.
Chemins des monstres : gameplay/navigation.gd.
Aspect provisoire des tours/monstres : rendering/board_renderer.gd.
Forêt, caverne et château : scenery.gd et assets/terrain/.
Flèche de l'archer : projectiles.gd et assets/projectiles/fleche.png.
Création des boutons : ui/build_interface.gd ; apparence : ui/control_factory.gd.
Textes actualisés pendant la partie : ui/update_interface.gd.
Texte détaillé des fiches : ui/inspection_text.gd.
Apparence de la fiche : inspection.gd ; position des commandes : ui_layout.gd.

LES COMMENTAIRES DANS LES SCRIPTS
Un paragraphe commençant par ## explique la fonction qui suit : son rôle,
ses paramètres utiles, son résultat et les modifications qu'elle réalise.
Un commentaire commençant par # explique une étape précise ou la raison
d'une vérification. Les lignes vides séparent les étapes d'une fonction.
Les mots anglais des noms de fonctions sont conservés pour retrouver les appels.
Les explications sont en français ; les intitulés historiques des tests restent en anglais.

LE VOCABULAIRE NÉCESSAIRE POUR COMMENCER
extends : indique la catégorie d'objet Godot utilisée par le fichier.
Node2D : un élément de scène qui peut avoir une position et dessiner en deux dimensions.
Control : un élément d'interface qui peut recevoir des clics et des touchers.
RefCounted : un objet de données ou d'aide qui n'a pas besoin d'être affiché dans une scène.
const : une valeur de référence qui ne sera pas réaffectée pendant l'exécution.
var : une variable ; le nom permet de retrouver la valeur plus loin dans la fonction.
var nombre: int : une variable dont le type est explicitement un entier.
var nombre := 3 : Godot déduit ici le type entier à partir de la valeur 3.
func : une fonction ; les paramètres à fournir sont entre parenthèses.
static func : une fonction appelée directement sur le script, sans créer un objet avec new().
-> bool : la fonction renvoie un vrai ou un faux ; -> void : elle ne renvoie pas de résultat.
return : quitte la fonction, et peut transmettre une valeur à celui qui l'a appelée.
if / elif / else : choisissent les instructions selon les conditions vérifiées.
for / while : répètent des instructions pour parcourir des éléments ou tant qu'une condition reste vraie.
continue : ignore la suite du tour de boucle actuel et passe au suivant.
Array : une liste ordonnée. Dictionary : des valeurs retrouvées grâce à leurs clés.
enemy.hp : ici, c'est la valeur de la clé « hp » dans le dictionnaire du monstre.
Vector2i : deux entiers, utilisés pour une case (colonne, ligne).
Vector2 : deux nombres avec décimales, utilisés pour une position précise ou une taille.
Rect2 : un rectangle, constitué d'une position et de dimensions.
signal : un événement auquel une autre partie du code peut réagir.
connect : relie une fonction à cet événement ; emit : annonce que l'événement a eu lieu.
func(): au milieu d'une instruction : une petite fonction sans nom, conservée pour être appelée plus tard.
await : attend un événement, comme la prochaine image, sans bloquer toute l'application.
delta / dt : une durée en secondes ; le commentaire de la fonction précise s'il s'agit de temps réel ou de jeu.
% dans une formule : le reste d'une division ; dans un texte : l'insertion de valeurs formatées.
res:// : la racine du projet. user:// : le dossier de données privées du jeu sur l'appareil.
_ready, _process, _draw, _gui_input : fonctions que Godot appelle aux moments correspondants.
L'indentation indique quels blocs appartiennent à une fonction, une condition ou une boucle.

VÉRIFIER APRÈS UNE MODIFICATION
Depuis le dossier du projet : godot --headless --path . --script tests.gd
Les scénarios sont classés dans tests/ ; tests.gd les lance tous et affiche le bilan.
Ne modifiez pas à la main les fichiers .uid ni le dossier .godot : Godot les gère.
Quand une règle change, actualisez aussi le commentaire qui l'explique.
